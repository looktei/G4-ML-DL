v.4 แก้ปัญหา dependency ต่อ folder original script โดยตรง: ทุกไฟล์ 00_*.py ถึง 27_*.py เป็น standalone script ที่ embed source ของขั้นนั้นไว้ในตัวเอง

  • เมื่อจบ จะ print [DONE] พร้อม result/return code และ path ของ status file
  • ยังเก็บ .stdout.log, .stderr.log, .status.json, .status.md ใน logs/ เสมอ

หมายเหตุ: ถ้าใช้เครื่องอื่นที่ CUDA/PyTorch version ต่างกัน ให้ปรับ PyTorch/PyG ตาม CUDA ของเครื่องนั้น แล้วรัน python 00_check_environment.py ซ้ำ

หลักการใช้ seed ใน handout นี้

  • --seed 42: ใช้เป็น single seed และใช้เป็น primary seed สำหรับ repeated-seed steps ถ้าไม่ได้ระบุ --primary-seed
  • --seeds 0-19: ใช้กับ repeated random/scaffold split steps เช่น classical validation, MLP, SMILES, ChemBERTa, GNN
  • --n-seeds 20: shortcut เทียบเท่า repeated seeds 0 ถึง 19
  • ไม่ได้ hard-code N=20 ใน script; ปรับเป็น N=5, 10, 50 ได้ตามงาน

ข้อควรระวังก่อนรันจริง

  • บาง original scripts จะเขียน output ไปที่ default folder เช่น data/modeling/ และอาจ overwrite ผลเดิม
  • ถ้าต้องการ sandbox run ให้ใช้ --extra-args "--output-dir ..." เฉพาะ step ที่ original script รองรับ
  • ขั้น BindingDB/PubChem อาจต้องใช้ไฟล์ external release หรือ internet access และใช้เวลานาน
  • สำหรับการตีพิมพ์ ให้เก็บ logs/*.status.json และ logs/*.status.md เป็น audit trail
